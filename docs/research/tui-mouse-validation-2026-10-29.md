## 实机反馈推动的修复

用户在 Windows Terminal 手工运行验证脚本，先报告了乱码并提供截图。问题来自 `BufferedStdout` 对 fd 1 直接写入 UTF-8 字节：Windows CP936 会误解码非 ASCII 字符，甚至消耗后续 ESC 字节，造成裸露的 `[39m`、`[22m`。现通过预先绑定的 Node TTY writer 输出完整帧，并用 StringDecoder 保留跨字节块的 UTF-8。CP936/CP65001 独立控制台对照验证了修复；用户随后确认显示和鼠标操作均正常。

用户又提供 `React error #185` 截图。完整 CLI 同样能复现，不能以此前组件测试通过作为完成依据。真实 Ink 调度下，流式测量、底部 sentinel 锚点和平滑滚动数值位置重复回写，累计嵌套更新。修复保留跟随锚点、移除禁用平滑滚动时的逐 token 状态镜像和回调，并提前跳过没有变化的更新。还修复了通知回调变化导致持久化管理器反复重建的问题。

- 四种既有工作模式、模型、当前会话 Thinking、审批队列、侧栏切换与关闭均有鼠标入口。审批状态标签仅打开队列，不改变审批策略。
