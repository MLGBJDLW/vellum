# Provider and model audit — 2026-10-29

This audit covers all 17 provider adapters. The shipped catalog is an offline selection aid for text, vision-input and tool workflows; it is not evidence that a particular account can invoke every listed model. `/model refresh <provider>` queries that provider's model endpoint on demand and updates the existing catalog. No background polling or second model registry was added. A failed refresh retains the prior view. Unknown prices and output limits remain unknown instead of being fabricated.

## Runtime changes and upstream comparison

[Pi's Responses adapter](https://github.com/badlogic/pi-mono/blob/main/packages/ai/src/api/openai-responses.ts) has an explicit Responses wire format, request cancellation, model-specific compatibility and a terminal-event check. Vellum applies those patterns inside the existing provider adapters. A missing terminal event is an error, and executable tool calls are released only after a completed response.

[Zed's Anthropic provider](https://github.com/zed-industries/zed/blob/main/crates/language_models/src/provider/anthropic.rs) treats authenticated model discovery as the current source and retains user-configurable models. Vellum keeps an offline catalog and adds explicit refresh to avoid startup network latency or a background polling mechanism. Pi's [generated model catalog](https://github.com/badlogic/pi-mono/blob/main/packages/ai/src/providers/anthropic.models.ts) also separates model metadata from transport implementation.

Signed/encrypted replay data is persisted on assistant messages, scoped to the original provider and model. Anthropic retains signed thinking blocks, OpenAI retains reasoning items, and compatible thinking APIs retain `reasoning_content`. Google retains native signed candidate parts because its signatures are attached to content parts; rewriting those assistant parts must drop their replay metadata. Summaries do not inherit it. The existing context manager uses the canonical catalog, including the currently selected provider, rather than another model-limit table.

OpenRouter's [`reasoning_details` contract](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens#preserving-reasoning) requires the original signed, summarized and encrypted sequence on tool continuation. Both completion and streaming paths retain these objects in the existing opaque replay metadata. Streaming chunks remain in arrival order, including repeated indices; display text is separate, and provider/model switches do not echo another route's replay data.

Explicit output budgets can use the selected model's documented limit; the default remains practical. Cancellation reaches SDK requests. Unknown model prices display as `Unknown`, and cost estimates do not present unpriced work as free. Catalog prices are snapshot estimates; promotions, context tiers, caching, regional rates and provider charges can change the actual bill.

The core cost service reads current prices from this same provider-scoped catalog, including explicit model refreshes. Historical exact-ID rates remain only for models absent from the current catalog; unpriced current entries never borrow a legacy price or another provider's rate.

## Verification boundary

SDK request/response fixtures verify Responses tool IDs, adaptive Claude requests, reasoning continuity, Gemini thinking levels, cancellation forwarding, provider isolation, catalog validation and session serialization. These checks do not establish paid inference success, account entitlements, or every provider's live availability. Only OpenRouter's public discovery endpoint was queried live in this audit; no paid completion was sent. Image/audio/video generation and vendor-hosted computer-use protocols are not added merely because a model family offers them.
