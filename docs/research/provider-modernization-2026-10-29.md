# Provider modernization follow-up — 2026-10-29

The starting commit already contained the flagship refresh documented in [the earlier audit](provider-model-audit.md). This pass rechecked all 17 adapters and found additional problems in catalog propagation, secondary provider coverage, reasoning formats, local endpoints, and request timeouts. It extends the existing catalog and adapter owners.

## Confirmed failures and repairs

- A successful `/model refresh` replaced `MODEL_CATALOG`, but adapter `listModels()` and `listModelsAsync()` still read imported static arrays. Four regression cases reproduced the stale lists across Anthropic, OpenAI, Google, and Groq. They now read the same provider catalog used by model lookup and the CLI.
- Discovery ignored Groq's `context_window` and `max_completion_tokens`, retained capabilities even when the endpoint explicitly reported `false`, and admitted speech/moderation products into the chat picker. Normalization now honors these fields, excludes incompatible Groq products and OpenRouter batch routes, and reads provider reasoning/lifecycle metadata.
- Mistral's reasoning responses return native thinking/text chunks, including mixed streaming chunks. The previous adapter forwarded those arrays as text. The existing adapter now separates display text from thinking and retains native thinking blocks for same-provider, same-model continuation.
- Groq's GPT-OSS models use `include_reasoning`; other reasoning routes use `reasoning_format`. Both now send their documented controls. Groq reasoning is display-only and is not echoed as the incompatible `reasoning_content` request field. Doubao's thinking toggle now reaches the root `thinking` request field.
- Ollama/LM Studio model listing and connectivity checks ignored configured base URLs and authentication headers. They now use the initialized endpoint and credentials. Ollama reads `/api/show` capabilities with at most four concurrent requests under one ten-second metadata deadline; LM Studio uses its bulk native model endpoint and falls back for older servers. Tool support has explicit unknown semantics: only a reported `false` suppresses requested tools. Bare names do not fabricate support or an output limit, and failed metadata inspection preserves existing known capabilities.
- OpenAI-compatible and Anthropic requests were forcibly aborted after 60 seconds even though the installed SDK defaults allow ten minutes. The adapter now leaves the SDK default intact and preserves explicit caller timeouts. Fake-clock request tests reproduce the old one-minute abort, verify survival after 60,001 ms, verify the user's 120-second override, and verify caller cancellation reaches the request.

## Upstream design comparison

[Pi's Responses adapter](https://github.com/earendil-works/pi/blob/main/packages/ai/src/api/openai-responses.ts) keeps wire compatibility and supported thinking controls explicit. [Hermes' model owner](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/models.py) combines curated fallback data with discovery and centralizes identity/metadata; it does not treat a discovered name as proof of capability. [Zed's Mistral provider](https://github.com/zed-industries/zed/blob/main/crates/language_models/src/provider/mistral.rs) translates native provider content into application events. [DeepSeek Harness](https://deepseek-harness.github.io/deepseek-harness/en/guide/providers) documents endpoint-specific protocols and treats listing failure as distinct from model unavailability. These support the same-owner approach here. Broader Codex/harness research is recorded in [agent-harness.md](agent-harness.md).

The installed [OpenAI SDK](https://github.com/openai/openai-node/blob/master/src/client.ts) and [Anthropic SDK](https://github.com/anthropics/anthropic-sdk-typescript/blob/main/src/client.ts) each use a 600,000 ms default. Explicit timeouts and abort signals remain authoritative; retry bounds are unchanged.

## Reproduction and verification

Run `pnpm exec vitest run packages/provider/src/__tests__/current-models.test.ts packages/provider/src/__tests__/local-discovery.test.ts --maxWorkers=1` for the focused contracts, then `pnpm -F @vellum/provider typecheck`. The provider fixture suite also covers existing tools, transforms, replay, credentials and registry behavior. No paid completion was sent and no live private provider key was used.

Review found that treating missing local tool metadata as `false` caused the core stream layer to remove all tools. Six real local HTTP fixture cases reproduced this before repair. After a provider build, `pnpm exec vitest run packages/core/src/session/__tests__/llm-local-discovery.test.ts --maxWorkers=1` exercises native discovery, catalog update, core `LLM.stream`, and the actual adapter request. It verifies supported, unsupported and unknown capabilities, plus authenticated discovery/connectivity/completion. Separate fake-clock cases verify bounded Ollama inspection concurrency, total deadline and caller cancellation.

Run `pnpm exec tsx scripts/update-openrouter-catalog.ts`, then format the generated file, to regenerate the offline shortlist through the same normalizer used by runtime discovery. This is a manual maintenance command, not startup network work or a new polling service. Model listings establish published metadata, not account entitlement or successful inference. Yi/Baichuan's current availability remains explicitly unverified.
